# تحديث الساعة العالمية — 5.0.0-dev15 — 2026-11-03

أكد صاحب المشروع نجاح dev14 في إزالة التجمد وتخصيص الأسماء. أُنجزت هذه المتابعة لتفعيل تحديث البيانات فقط. **قبول سلوك التحديث داخل NVDA من صاحب المشروع لا يزال مطلوبًا قبل إغلاقها.**

## التشخيص المثبت

كان dev14 يحاول جلب https://raw.githubusercontent.com/alialomari-coder/awqati-data/main/world-clock/manifest.json . المستودع متاح، لكن فحص Contents API الرسمي أعاد 404 لملف البيان؛ القناة المجهزة محليًا لم تُنشر أصلًا. وفشل HTTPS المباشر إلى raw.githubusercontent.com في بيئة التنفيذ برسالة SSL connection could not be established. لا تكفي هذه النتيجة لإثبات خطأ DNS أو شهادة بعينها على جهاز المالك، ولم أنسبها إليه. السبب البنيوي المثبت أن الملف المطلوب غائب، فلا يمكن إكمال تحقق موقّع. ليست حالة «لا يوجد تحديث»، وليست رفض توقيع بعد تنزيل بيان صحيح.

أُعيد استخدام RSA وSHA-256 والتحقق المرحلي والاسترجاع الموجودين. نُقلت نقطة الوصول إلى GitHub HTTPS Contents API بعد نجاح اختبار urllib العام دون مصادقة؛ لا تعطيل للتحقق من شهادات HTTPS ولا رمز GitHub داخل الإضافة.

## الاختبار الفعلي وقواعد IANA

نجح اتصال HTTPS العام دون مصادقة، والتحقق بالمفتاح المثبت، وتنزيل الأرشيف المنشور وفحصه وتفعيله، ثم تحقق عدم وجود تحديث آخر دون تنزيل أرشيف، والاسترجاع والعمل دون شبكة. الأدلة في world_clock_update_live.json وworld_clock_update_live_nvda_runtime.json. الثاني شغّل Python 3.13.15 المرفق فعليًا مع NVDA، في عملية مستقلة؛ لا تثبيت أو تغيير في NVDA الشخصي.

نجح أيضًا تشغيل زر wx الأصلي نفسه من النافذة العربية، بأحداث الأزرار الفعلية وعامل الإنتاج والقناة المنشورة: فعّل .3، ثم أعلن في الضغطة الثانية «بيانات الساعة العالمية محدثة»، دون تغيير ملف المدن والاسم المخصص، مع معالجة أحداث GUI أثناء التنزيل. الدليل world_clock_update_live_button.json. يظل هذا خارج عملية NVDA الشخصية، فلا يُدّعى اختبار النطق والبرايل فيها.

لم أكتف بتغيير اسم مدينة: أُنشئت نسخة اختبار مؤقتة من قواعد IANA 2026c الموجودة سابقًا بالمشروع، ثم نزّلت القناة الحقيقية 2026f. عند 2026-11-01T06:00Z تغيرت هافانا من -300 إلى -240 دقيقة عن UTC بعد التفعيل، بسبب تغير القاعدة الفعلية. طوكيو بقيت +540 دقيقة. الدار البيضاء كانت صفرًا في النسختين عند هذا التاريخ، ولم تُقدّم باعتبارها تغييرًا. أثبت الفحص إنشاء provider وكائنات مناطق جديدة بدل الذاكرة القديمة، وبقاء ترتيب المدن والتخصيص العربي والإنجليزي وملف المستخدم نفسه. لا إعادة تشغيل لازمة.

أول إصدار عام .3 يحتوي IANA 2026f مثل المضمن في dev14؛ رفع رقم إصدار البيانات هنا ينشر القناة ويتيح التوزيع الموثوق، ولا يدعي اكتشاف قاعدة IANA أحدث. اختبار 2026c إلى 2026f يثبت قدرة الآلية على تغيير القواعد وقتيًا من بيانات أقدم فعلية، وليس قاعدة مصطنعة أو فرق UTC ثابتًا.

تختبر المجموعة المحلية أيضاً HTTP على 127.0.0.1، والتوقيع والتلف وعدم التوافق والتراجع وفشل الشبكة والانقطاع والكتابة والاستعادة. لا تعتمد المجموعة الكاملة على الإنترنت. يحتاج خادم الاختبار المحلي إلى إذن مقابس في بيئة العزل؛ شُغلت البوابة بإذن ذلك بدل تخطي الاختبار. الأمر المستخدم فعليًا هو python tools/run_checks.py.

## الأسبوعي واليدوي

مربع «تحديث البيانات تلقائيًا» في نهاية واجهة الساعة العالمية، قرب الزر، محدد افتراضيًا. تحفظ حالته في world_clock_updates.json داخل بيانات أوقاتي، منفصلة عن المدن والتخصيصات. lastSuccessfulCheck وlastDataUpdate حقلا UTC مستقلان؛ عدم وجود تحديث يغير الأول وحده، والفشل لا يغير أيًّا منهما. تحفظ أسباب الفشل تشخيصيًا في lastError، مع عداد المحاولات وموعدها. لا بيانات سرية أو رمز مصادقة.

عند بدء الإضافة يحسب الموعد من آخر تحقق ناجح زائد سبعة أيام، مع احترام موعد إعادة المحاولة. يستخدم wx.CallLater واحدًا للموعد، ودقيقة تأجيل أولية على الأقل، دون مؤقت فحص دائم. يعاد ضبط الموعد بعد انتهاء العملية، فيخدم الجلسات الطويلة أيضًا. التحقق اليدوي يتجاوز الفاصل وحالة التفعيل، ويمنع بدء عامل ثان إن كان أحدهما يعمل.

الفشل التلقائي صامت بلا نافذة أو نقل بؤرة أو نطق؛ تتدرج الإعادة بعد ساعة ثم ست ساعات ثم يوم ثم أسبوع، وبعدها أسبوع لكل فشل مستمر. لا تُحدّث تواريخ النجاح عند الفشل. التعطيل يلغي الموعد والتحقق التلقائي الجاري قبل اعتماده، ولا يمنع اليدوي. الإغلاق يلغي النتائج المتأخرة والمواعيد. نجاح تحقق بلا تغيير صامت؛ تفعيل إصدار فعلي يعلن بعد انتهاء التنبيهات الحالية/المنتظرة المهمة، باستخدام أولوية NEXT الأصلية في NVDA. يحد الانتظار بعشر دقائق لتجنب مؤقت إشعار عالق؛ البيانات تظل مفعلة حتى إن تعذر الإعلان في تلك المدة.

تتم الشبكة والتحقق الكبير وفك الأرشيف وقراءة TZif والتفعيل في عامل خلفي. تبني GUI مراجع البيانات المحضرة مرة واحدة. كتابة الحالة الصغيرة ذرية. لا تقرأ إشعارات الوصول ملفات الشبكة ولا تنفذ تنزيلات.

رسائل اليدوي منفصلة: جار التحقق، البيانات محدثة، تم تحديثها، تعذر الاتصال، تعذر التحقق مع حفظ السابق، أو أن الإصدار يتطلب أوقاتي أحدث. يحتفظ أي مسار فشل بالمدن والترتيب والأسماء. لا يتغير الاختصار NVDA+Ctrl+F12 أو بقية الأدوات وقواعد بياناتها.

## صيانة القناة والمفاتيح

المفتاح الخاص محفوظ محليًا في development_baseline/world-clock-signing-key.pem، خارج الحزمة وGit وDrive؛ لا يعرض محتواه ولا ينشر. احفظ نسخة احتياطية محمية خارج المستودع. فقد المفتاح يتطلب إصدار إضافة جديدًا يثبت مفتاحًا عامًا موثوقًا؛ لا تدور المفاتيح اعتمادًا على بيان غير موثوق. tool يطابق المفتاح الخاص بالمفتاح العام المثبت قبل توقيع أي شيء.

إعادة تجهيز الإصدار الحالي للمراجعة فقط، دون نشر:

```powershell
python tools/publish_world_clock_channel.py --output delivery-local/world-clock-dev15/reprepared-channel --private-key development_baseline/world-clock-signing-key.pem --version 2026-11-03.3
```

لإصدار IANA جديد، يجلب المسؤول عجلة tzdata الرسمية ويثبت بصمتها من PyPI أولًا. تقبل الأداة --tz-wheel مع مسار العجلة و--tz-source-url مع رابطها الرسمي، وتعيد بناء TZif في مساحة مؤقتة، وتقرأ إصدار IANA وtzdata من العجلة، وتجدد البصمات، وتتحقق من جميع المناطق. لا تستبدل قواعد ملفات مستخدم قيد التشغيل أثناء البناء. أعط إصدار بيانات أعلى جديدًا ولم تمس الأرشيفات القديمة. هذه معاملات صيانة يحددها المسؤول بناء على الإصدار الحقيقي؛ لا تلصق رابطًا أو إصدارًا مخمنًا.

لتحديث المدن/CLDR، أعد بناء المصدر المراجع بأدوات audit_world_clock_sources.py وbuild_world_clock.py وbuild_world_clock_channel.py وفق المصادر والأدلة في world_clock_source_review.md. حدّث معايير المصادر المثبتة عند تغير الإصدار، ولا تعتمد مدخلات جديدة بلا فحص جغرافي ولغوي وتغطية. مرر جذر البيانات المجهز والمفحوص عبر --source إلى ناشر القناة. يحفظ المرجع المعرفات الثابتة. لا يكتب الناشر تخصيصات المستخدم في القاعدة.

اختبر بيان الإصدار والتوقيع والبنية وحالات التوقيت الصيفي وتحديثًا فعليًا محليًا أولًا. إضافة --publish تنشر **ثلاثة مسارات بيانات فقط** عبر Git trees API في world-clock-data، مع تحديث غير قسري يحمي من ناشر متزامن. لا push لـmaster، ولا release للإضافة، ولا حذف أرشيفات قديمة. تحقق بعد النشر بتشغيل tools/world_clock_live_probe.py وبمقارنة الالتزام ومساراته. لا ترفع المفتاح الخاص أو أدلة المستخدم الشخصية ضمن التسليم.

## تجربة صاحب المشروع

1. ثبت dist/awqati-5.0.0-dev15.nvda-addon وأعد تشغيل NVDA. ادخل الإعدادات بـNVDA+Alt+A، الساعة، الساعة العالمية. يبقى اعتماد dev14 السابق مسجلًا.
2. تأكد أن «تحديث البيانات تلقائيًا» محدد. اضغط «تحديث البيانات»؛ أول مرة يفترض أن يفعّل .3، ثم الضغط مرة ثانية يعلن أن البيانات محدثة، دون تغيير المدن والأسماء والترتيب.
3. عطّل المربع وأعد التحقق اليدوي؛ يجب أن يظل فعالًا. أغلق الإعدادات وافتحها وأعد التشغيل للتحقق من حفظ الاختيار. أعد تفعيله للاستخدام الأسبوعي.
4. اختبر دون إنترنت: اليدوي يعلن فشل الاتصال وتبقى الأوقات. التلقائي لا يصدر رسالة أو يحرك البؤرة. لا يلزم الانتظار أسبوعًا لقبول البناء؛ أثبتت اختبارات الساعة المحاكاة حدود الأسبوع ومواعيد الإعادة، وتُراجع التواريخ عند حدوثها طبيعيًا.
5. راجع استعلام المدن بضغطاته الثلاث والتخصيص العربي والإنجليزي والمنبهات والمؤقتات وساعة الإيقاف. أبلغني بنتيجة اليدوي والمربع والنطق وبرايل إن توفر. لا تثبيت أو تغيير لإعداداتك الشخصية نُفّذ آليًا خلال العمل.
